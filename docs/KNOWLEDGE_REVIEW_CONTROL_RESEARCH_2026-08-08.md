# 资料研究与审阅闭环调研

日期：2026-08-08  
范围：资料来源、集合与标签、笔记、局部摘录、翻译、跨项目引用、任务追踪和
质量门禁

## 1. 结论

本轮采用两个彼此独立但可交接的平台能力：

1. 参考资料与知识库负责保存“依据从哪里来”，包括原始资料、来源、标签、笔记、
   译文、局部摘录和项目引用。
2. 审阅任务与质量门禁中心负责保存“什么需要改、怎样算完成、哪个版本验证过”。

它们不合并成一套万能数据库。专业工作台继续拥有画面、研究结果和资产项目；
平台只保存跨项目索引和用户明确交接的数据。

## 2. 资料组织参考

Zotero 的集合模型允许同一条目同时属于多个集合而不复制文件；标签用于主题、
方法和工作状态等细粒度描述。这支持 GATalk 继续使用“规范条目 + 多集合成员关系
+ 标签”，而不是按文件夹复制原画。

Zotero 同时区分隶属于具体条目的子笔记和独立笔记，并允许笔记参与标签、关联和
搜索。GATalk 当前先实现独立项目笔记、条目研究笔记和局部图片摘录；不在本轮
引入完整富文本编辑器。

Zotero 的 PDF 标注会保留返回原页的上下文链接。对应到图片研究，GATalk 的局部
截图必须保存父条目和归一化区域，避免裁切图脱离原画语境。

参考：

- https://www.zotero.org/support/collections_and_tags
- https://www.zotero.org/support/notes
- https://www.zotero.org/support/pdf_reader

## 3. 来源与翻译边界

- 原画和文档由用户主动导入，保留原始字节和 SHA-256。
- ArtStation、文章和教程只记录用户输入的 URL，不自动抓取、绕过登录或复制站点
  内容。
- 翻译只处理用户粘贴并确认发送的文字。图片、本地路径、其他资料和 API Key 不
  进入请求。
- AI 译文记录供应商和模型，并与用户手写译文区分；Mock 不冒充真实翻译。
- 当前没有网页浏览器剪藏器、OCR、全文 PDF 标注和自动网页翻译。这些属于后续
  候选，不伪装为已完成能力。

## 4. 审阅追踪参考

成熟需求追踪强调把需求、测试或验证结果与具体版本/构建关联，并保留状态变化和
历史，而不是只维护一张“待办清单”。Azure DevOps 的需求可追踪与工作项历史
文档支持这一原则。

GATalk 因此把每个审阅任务绑定来源模块、项目、对象和可选来源版本；后续复查以
追加记录保存版本、结果和证据。质量门禁同样保留逐版本评估，不能用最后一次状态
抹去早期失败。

参考：

- https://learn.microsoft.com/en-us/azure/devops/pipelines/test/requirements-traceability?view=azure-devops
- https://learn.microsoft.com/en-us/azure/devops/boards/queries/history-and-auditing?view=azure-devops

## 5. 未采用的做法

- 不自动把所有 AI 结论转成任务；用户必须选择，防止任务中心被低置信度文字淹没。
- 不用 0–10 总分作为质量门禁；通过条件必须能被版本和证据验证。
- 不让审阅中心直接写入三个不同项目格式；这会造成强耦合和并发风险。
- 不自动抓取 ArtStation 或其他站点；来源授权、页面结构和网络可用性不稳定。
- 不加入新运行依赖、本地大模型、CUDA 或后台网络服务。
