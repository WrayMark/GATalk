# 审阅任务与质量门禁中心架构

## 1. 模块位置

- 模块 ID：`gatalk.review_control`
- 工作区 ID：`review_control`
- 层级：平台层
- 本地数据：`%LOCALAPPDATA%/GATalk/review-control/review_center.json`

平台层不依赖场景审阅 SQLite、作品研究 JSON 或资产拆分 JSON 的内部表结构。
专业工作台通过稳定的任务交接字典发送用户确认内容。

## 2. 任务模型

`ReviewTaskRecord` 保存：

- 任务标题、处理说明、验收条件、优先级和状态；
- 来源模块、项目 ID、项目标题和项目路径；
- 来源对象类型、对象 ID 和来源版本；
- 标签与创建、更新时间。

同一 `source_module_id + source_project_id + source_entity_type +
source_entity_id` 只建立一条任务，避免重复点击产生副本。

## 3. 版本复查

`TaskVerificationRecord` 以追加方式保存版本名称、版本 ID、复查状态、证据摘要、
备注和时间。允许状态为：

- 已改善
- 无明显变化
- 进一步偏离
- 已解决
- 证据不足

旧记录不会因任务状态改变而删除。

## 4. 质量门禁

`QualityGateRecord` 保存名称、维度、验收条件、是否必需、所属项目和当前状态。
`GateEvaluationRecord` 保存每个版本的评估和证据。

当前状态是最近一次评估的便捷读数；完整判断历史以评估记录为准。门禁由用户
定义和确认，系统不生成综合分数。

## 5. 模块交接

- 场景美术控制：用户确认的审阅发现、灯光标注任务和优化预演任务。
- 作品研究：当前选中的研究维度及观察、证据、学习点与不确定性。
- 资产拆分：用户选中的资产及类别、层级、制作策略、证据和不确定性。

交接只复制任务所需的文字和来源标识，不发送图片，不包含 API Key，也不自动
改变来源项目。来源项目删除或移动时，已有任务保留，但路径可能需要用户更新。

## 6. 数据安全与恢复

- JSON 使用原子写入，手动备份进入 `backups`。
- 导出只包含任务、门禁、来源标识和复查历史，不包含项目图片或凭据。
- 高版本格式拒绝打开，避免旧软件覆盖新数据。
- 当前为单机个人工作流；跨进程同时编辑全局审阅中心尚未作为多人协作能力提供。

## 7. 扩展位置

未来可增加项目筛选、来源路径修复、门禁模板、任务与项目内对象双向跳转、证据
附件索引和团队协作导出。动态插件、云账户和未知代码加载不在当前范围。
