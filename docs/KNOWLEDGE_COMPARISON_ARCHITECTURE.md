# 参考资料平台与作品对照研究架构

## 层级

```text
GATalk 应用外壳
├─ 平台层
│  └─ 参考资料与知识库
│     ├─ 美术参考资料（已启用）
│     ├─ 关卡设计资料（已注册，未启用）
│     └─ 策划与系统资料（已注册，未启用）
└─ 专业工作台层
   ├─ 场景美术控制
   ├─ 作品研究
   ├─ 资产拆分工作台
   └─ 作品研究集合与对照研究
```

平台层管理可跨任务复用的信息，专业工作台管理具体项目状态和计算结果。平台层
不能依赖某个专业工作台的数据表；工作台通过有版本的交接数据接收资料快照。

## 注册契约

`WorkspaceDescriptor` 增加：

- `level`：`platform` 或 `professional`
- `parent_workspace_id`：可选上级平台入口
- `category`：入口分类，不参与业务判断

`KnowledgeDomainDescriptor` 表示资料域；`HandoffDescriptor` 表示受支持的模块交接。
这些是可信内置模块注册，不执行未知代码。

## 资料库数据

资料库目录：

```text
library.json
assets/
derived/
documents/
exports/
backups/
```

核心实体：

- `KnowledgeItem`：规范条目、领域、来源类别、SHA-256、作者、项目、标签、笔记、
  原文、译文、父条目和可选归一化截图区域。
- `KnowledgeCollection`：领域内的层级集合。
- `memberships`：条目到多个集合的关系；不会复制条目或原始文件。
- `KnowledgeProjectReference`：资料到场景审阅、作品研究、作品对照或资产拆分
  项目的显式引用。

导入文件按 SHA-256 去重，保留原始字节。网页条目只保存用户输入的 URL，默认
标记为尚未核实，不自动联网。保存采用原子 JSON 替换；手动备份进入 `backups`。

资料库格式 v2 增加局部截图、翻译和跨项目引用。打开 v1 前先把入口保存到
`backups/pre-migration-v1-library.json`。局部截图从经 EXIF/ICC 处理的显示图建立，
只写入 `derived`；导入的原始字节不改变。

翻译通过 `StructuredOutputProvider` 运行。用户必须查看发送范围并确认；请求只含
原文和专业上下文，不含图片、本地路径或资料库其他条目。译文记录供应商、模型和
更新时间，用户手动修改后标记为用户修订。

## 对照研究数据

项目目录：

```text
comparison.json
assets/
artifacts/
exports/
backups/
```

每件作品保存图片哈希、只读副本、来源类型、资料库引用、本地分析、人工观察。
研究状态保存核心问题、已知背景、选择的比较维度、当前 2–6 件作品、本地差异、
AI 结果、综合笔记、可迁移规律和边界。

从资料库交接时复制图片字节并保存 `library_id:item_id` 来源引用。复制后双方独立
保存，防止资料库整理动作破坏既有研究结果。

## 分析与 AI

本地分析复用作品研究的线性 sRGB 明度、三阶明度、饱和度、中性色、Oklab 色板
和边缘密度。差异以活动作品列表中的第一件为基准；用户可用“设为基准”显式更换，
结果类型固定为“测量”。

`ComparativeArtworkReview` 通过现有 `VisionReviewProvider` 调用，接受 2–6 张图、
研究问题、本地测量和选择维度，使用严格 JSON Schema。输出不使用总分，必须区分
共同点、差异、证据、视觉作用、解释、置信度和研究边界。

## 全局任务、安全与恢复

- `RuntimeTaskCenter` 记录任务元数据、供应商、模型、进度、重试和脱敏错误。
- 不保存 API Key、图片字节、完整提示语或请求正文。
- 上次进程中的运行任务重新加载时标记为“上次退出时中断”。
- `ApplicationSessionGuard` 只记录当前进程会话；正常退出删除标记。
- 项目诊断检查入口、数据库、assets 和备份，不读取图片内容，不自动修复项目。
- 诊断报告明确列出隐私边界。

## 迁移与兼容

对照研究仍使用独立 JSON 格式版本 1，不修改现有 `project.db`，因此旧项目无需迁移。
资料库使用格式版本 2，并在入口升级前备份。
原有三个工作台仍使用相同入口和业务存储。工作台注册扩展字段均有默认值，现有
四参数注册代码与测试保持兼容。
